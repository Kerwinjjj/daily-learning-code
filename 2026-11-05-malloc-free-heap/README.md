# 堆内存：malloc / free、野指针、内存泄漏（Day5 · 固件头号 bug 来源）

> 以**代码和注释**为主，图表用于**比对**；英文缩写标注中文。UB = Undefined Behavior（未定义行为）。

## 0. 栈 vs 堆：先看清两者区别

| 对比项 | 栈（stack） | 堆（heap） |
|---|---|---|
| 谁分配 | 编译器自动（函数调用时） | 手动 `malloc`（memory allocation，内存分配） |
| 谁释放 | 函数返回自动回收 | 手动 `free` |
| 速度 | 极快（只移动栈指针） | 慢（要查空闲块、维护链表） |
| 大小 | 小（单片机常几 KB，PC 几 MB） | 大（受 SRAM 静态随机存取存储器 总量限制） |
| 生命周期 | 与函数同生共死 | 从 `malloc` 到 `free` |
| 典型风险 | 栈溢出（大数组、深递归） | 泄漏、野指针、碎片 |
| 嵌入式建议 | 局部变量、小数组首选 | **能不用就不用** |

**一句话：栈是自动的，堆是手动的。** 手动就要承担手动出错的风险 —— 本课三个坑全部来自"手动"这个环节。

## 1. malloc / free 的四个必做动作

```c
int *p = (int *)malloc(n * sizeof(int));   /* ① 返回 void*（无类型指针），强转成 int* */
if (p == NULL) { /* 处理分配失败 */ }      /* ② 必须判断返回值 —— 坑 1 */
/* ... 使用 p[i] ... */
free(p);                                   /* ③ 归还堆内存 */
p = NULL;                                  /* ④ 立刻置空 —— 坑 2 */
```

两个细节：

| 细节 | 说明 |
|---|---|
| 为什么写 `n * sizeof(int)` | 大小跟着类型走，换平台/换类型自动适配；写死 `20` 是低级 bug 的来源 |
| 为什么显式强转 | C 里 `void*` 可隐式转换，但显式更清晰；C++ 必须强转 |

## 2. demo1：正确封装（实测已跑通）

```c
/* 动态创建 int 数组：分配前判断 NULL */
int *create_int_array(size_t n)
{
    int *p = (int *)malloc(n * sizeof(int));   /* 用 sizeof 算大小，别写死 4 或 20 */
    if (p == NULL) {                           /* 坑1：分配失败必须判断 */
        printf("malloc failed (request %zu bytes)\n", n * sizeof(int));
        return NULL;
    }
    for (size_t i = 0; i < n; i++) {
        p[i] = (int)(i * 10);                  /* 这段内存现在归你，随便读写 */
    }
    return p;
}

/* 释放数组：free 之后把调用者的指针置 NULL */
void free_int_array(int **pp)                  /* 收二级指针，才改得到调用者手里的指针 */
{
    if (pp == NULL || *pp == NULL) return;     /* 防重复释放：已经是 NULL 就什么都不做 */
    free(*pp);
    *pp = NULL;                                /* 坑2：置 NULL，防止野指针 */
}
```

**为什么释放函数必须收 `int **pp`？** C 是按值传递：传 `int *p` 进去，函数里拿到的只是**副本**，`p = NULL` 只改了副本；收 `int **` 才是"改到调用者那个变量本身"。

**实测输出：**

```
arr[0] = 0
arr[1] = 10
arr[2] = 20
arr[3] = 30
arr[4] = 40
after free: arr = 0000000000000000
ok: 指针已置空，后续误用会立刻暴露
malloc failed (request 4611686018427387904 bytes)
big array = NULL：分配失败，但程序没崩（因为判断了）
```

最后两行是**坑 1 的实证**：申请约 4 EB 的内存必然失败，`malloc` 真的返回了 `NULL`。因为判断了，程序安然退出；不判断就是 `NULL` 解引用直接崩溃。

## 3. demo2：错误版（free 后不置 NULL，继续解引用）

```c
int *p = (int *)malloc(sizeof(int) * 3);
p[0] = 111; p[1] = 222; p[2] = 333;   /* 错误1：没判断 NULL 就用 */
free(p);                                /* 错误2：free 之后没有 p = NULL */
printf("after free : p[0]=%d p[1]=%d p[2]=%d\n", p[0], p[1], p[2]);  /* 错误3：野指针读 */
p[0] = 999;                             /* 错误4：往已释放内存里写 */
```

**实测输出（注意：程序不崩溃、不报错）：**

```
before free: p[0]=111 p[1]=222 p[2]=333
after free : p[0]=111 p[1]=222 p[2]=333
after write: p[0]=999
```

**编译器其实已经警告了**（`gcc -Wall` 会报 3 处 `-Wuse-after-free`）：

```
warning: pointer 'p' used after 'free' [-Wuse-after-free]
   37 |     printf("after free : p[0]=%d ...", p[0], p[1], p[2]);
      |                                         ^
   33 |     free(p);
      |     ^~~~~~~  note: call to 'free' here
```

警告不是错误，编译照样通过。**忽略警告 = 忽略掉最便宜的一道防线。**

**为什么"看起来一切正常"？** `free` 只是把这块内存标记为"可再次分配"，**不保证立刻还给系统**，内容留在原处。所以这次读得到旧值，写也"成功"。

| 情况 | 表现 | 后果 |
|---|---|---|
| 内存还没被复用 | 读写全成功，程序正常 | 你以为代码是对的，测试也过 |
| 已被别处 `malloc` 拿走 | 你的 999 覆盖了别人的数据 | 别处变量莫名变化 → 随机崩溃、数据错乱 |
| 已被系统回收 | 访问触发内存保护 | 段错误直接崩溃 |

这属于 **UB（未定义行为）**：标准完全不对结果做任何保证。**"这次没崩"绝不是"代码正确"的证据。**

## 4. 三大坑汇总

| 坑 | 错误写法 | 后果 | 正确做法 |
|---|---|---|---|
| ① 不判断返回值 | `p = malloc(...); p[0] = 1;` | 分配失败时 `NULL` 解引用 → 崩溃；单片机里是 HardFault（硬件错误）死机 | `if (p == NULL) { 处理 }` |
| ② free 后不置 NULL | `free(p); p[0] = 1;` | 野指针，读写已释放内存，破坏别人数据 | `free(p); p = NULL;` 连着写 |
| ③ 忘记 free | 循环里 `malloc` 不配 `free` | 内存泄漏，长期上电耗尽 SRAM | 成对释放；嵌入式尽量别动态分配 |

## 5. 野指针的产生情况（思考题①）

| 来源 | 代码示例 | 原因 |
|---|---|---|
| **free 后不置 NULL** | `free(p);` 之后继续 `*p` | 堆内存已归还，指针还指着那块地 |
| **指针未初始化** | `int *p; *p = 1;` | `p` 里是随机垃圾地址 |
| **返回栈上变量的地址** | `int *f() { int a[5]; return a; }` | 函数一返回栈帧就销毁 |
| **越界写坏指针** | `buf[10] = x;` 越界 | 把相邻的指针变量本身改成了野地址 |
| **指向已失效对象** | `realloc` 后用旧指针、结构体释放后还用其成员指针 | 对象没了，指针还留着 |

**四条防线：** 定义时就初始化 `= NULL` → `free` 后立刻置 `NULL` → 每次使用前判空 → 绝不返回栈地址。

## 6. 单片机里内存泄漏的后果（思考题②）

PC 上泄漏顶多越来越卡、重启就好；**单片机是长期上电的，重启一次就是一次事故。**

| 环节 | 具体后果 |
|---|---|
| 内存本来就少 | STM32F407 只有 192 KB SRAM，堆区常配置几 KB～几十 KB |
| 时间放大 | 连续运行几个月，每秒漏 50 字节 → 几周就见底 |
| 分配失败 | 堆耗尽后 `malloc` 一直返回 `NULL` |
| 连锁崩溃 | 没判断 `NULL` → `NULL` 解引用 → **HardFault** → 看门狗复位或死机 |
| 更隐蔽的碎片 | 总量还有，但没有**连续**大块，大块 `malloc` 失败、小块成功；反复分配/释放不同大小最易碎 |

**排查与预防：**

- 每次 `malloc` 记录字节数、`free` 扣减，打印当前占用（最土但最有效）；
- 看链接脚本里的堆区大小，统计"历史最高水位"；
- **工程实践**：能静态就静态（全局数组 / 静态内存池 memory pool），启动阶段一次性分配好，运行中不做频繁 `malloc/free`；用 RTOS（实时操作系统）时用它的内存管理接口，自带统计。

## 7. 口述题答法（四层）

**野指针：** ① 先定义（指向无效内存的指针）→ ② 五种来源（free 不置空、未初始化、返回栈地址、越界、对象已失效）→ ③ 危害（UB，可能不崩但破坏数据，最难查）→ ④ 防（初始化 NULL、free 置 NULL、用前判空、不返回栈地址）。

**内存泄漏：** ① 定义（申请了没还，堆越用越少）→ ② 单片机特殊在长期上电，泄漏会累积 → ③ 表现：`malloc` 返回 NULL → 未判断则 NULL 解引用 → HardFault 死机；加上堆碎片导致大块分配失败 → ④ 防：成对 free、尽量静态分配、做堆用量统计。
